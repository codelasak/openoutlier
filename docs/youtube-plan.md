# YouTube support: plan

Add YouTube channels (long-form videos and Shorts) to OpenOutlier the same way TikTok was added in `0b1a396`: passive capture in the page, a pure parser, the panel, overlay, Library and MCP tools. Video files are downloaded by yt-dlp on the Mac, through the bridge.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Data source | Read what youtube.com already loads (`ytInitialData`, `ytInitialPlayerResponse`, `/youtubei/v1/*` responses). No API key in v1. | Same promise as IG and TikTok: no account, no extra requests. |
| Parser | Our own `src/youtube.js` (pure functions, no deps). Field paths borrowed from YouTube.js (MIT), yt-dlp and Invidious; no code copied. | The extension has no build step; youtubei.js is 16 MB and needs a bundler. |
| Account id | `yt/<handle>` (lowercase, without `@`). Channels with no handle: `yt/UC…` channel id. | Matches `tt/` and `r/`. |
| Outlier median | Separate medians for **Shorts** and **long-form** inside one channel. | Shorts get far more views; mixing them makes every Short an outlier. |
| Cover | Extension, `chrome.downloads`: `maxresdefault` → `sddefault` → `hqdefault` from `i.ytimg.com/vi/<id>/`. | Public, stable URLs. |
| Video file | yt-dlp + ffmpeg on the Mac, started by the bridge (panel button) or by MCP `download_reel`. | YouTube streams through SABR + PO tokens; the extension can't get a plain mp4. |
| Downloads policy | Local-only feature, same as IG/TikTok downloads; README says it uses yt-dlp and is for personal research. | YouTube's terms don't allow downloading outside its own features. |

## What we collect

**Channel tabs** (`/@name/videos`, `/@name/shorts`, `/@name/streams`; first page from `ytInitialData`, then `/youtubei/v1/browse` continuations while scrolling):
video id, title, thumbnail, **rounded** views ("1.2M views"), length, **relative** date ("3 weeks ago"), live/premiere/members-only badges. The Shorts tab has no date at all.

**Watch / Shorts page** (`ytInitialPlayerResponse` + `ytInitialData`, and `/youtubei/v1/player` + `/next` on in-app navigation):
exact views, likes, comment count, exact publish date, description, keywords/tags, category, chapters, caption tracks (transcript available or not, auto-generated or not), the **most-replayed heatmap** (videos with roughly 50K+ views), channel subscriber count.

**yt-dlp info JSON** (when a video is downloaded): exact stats, timestamp, tags, chapters, heatmap. These values are written back to the library.

### Post record (same shape as TikTok, `platform: 'youtube'`)
`code` (11-char video id), `url`, `owner` (`yt/…`), `author`, `ownerId` (UC… channel id), `ownerName`, `ownerPic`, `type` (`short` | `video` | `live`), `takenAt`, `dateApprox`, `views`, `viewsApprox`, `likes`, `comments`, `duration`, `caption` (title), `description`, `hashtags`, `keywords`, `category`, `chapters`, `heatmap` (100 normalized values), `hasCaptions`, `thumb`, `files: []`, `seenAt`.

`viewsApprox` / `dateApprox` stay true until a watch-page visit or yt-dlp fills in exact values. Best-time analytics use **exact dates only**, and the panel says how many videos still have approximate dates.

## Phases

### 0. Fixtures (first)
- Capture real responses into `dev/youtube/`: channel Videos tab HTML, Shorts tab HTML, a browse continuation, a watch page, a `/player` and a `/next` response, and a Short page.
- Confirm the current item shapes: `richItemRenderer`/`videoRenderer` vs `lockupViewModel`, `reelItemRenderer` vs `shortsLockupViewModel`, where the heatmap lives (`markersMap` / `heatMarkers`), and how the like count is labeled.
- `dev/make-youtube-fixture.mjs` trims and anonymizes them, like `make-tiktok-fixture.mjs`.

### 1. Channel capture and panel
- `src/youtube.js`: `parseBrowse`, `parseInitialData`, `parseWatch`, `ytId`, `isYouTubeId`, text helpers (`simpleText`/`runs`/accessibility labels, "1.2M" → number, "3 weeks ago" → approximate timestamp, "12:34" → seconds).
- `src/hook.js`: on youtube.com forward `/youtubei/v1/(browse|next|player|reel/…)` responses that contain `"videoId"`.
- `src/youtube-content.js`: reads `ytInitialData` from the first HTML, listens for `yt-navigate-finish` (YouTube is a SPA), saves posts per account, and drives auto-scroll on the Videos/Shorts tabs.
- `manifest.json`: youtube.com content scripts; host permissions for `*.youtube.com`, `i.ytimg.com`.
- `src/metrics.js`: median per (account, Shorts/long-form); engagement = likes + comments where known; CSV/JSON columns.
- `src/panel.js`: YouTube mode with a **Videos / Shorts** switch; sort by views, Viral Score, length, date; outlier filter; analytics: length buckets, title words, hashtags, Shorts vs long-form, best time (exact dates only).
- Cover download from the panel.
- Tests: `tests/youtube.test.js` on the fixtures.

### 2. Watch page: exact stats and the overlay
- Parse the watch and Shorts pages; merge exact values into the saved post (exact views and dates replace approximate ones).
- `src/overlay.js`: toolbar on `/watch` and `/shorts/` with cover, video (via bridge) and a stats card (× median, Viral Score, heatmap peaks such as "most replayed at 0:42").
- **Get exact stats** in the panel: opens the top N outliers' watch pages one at a time in a background tab (throttled, as `refresh_reel` does), so dates and views become exact where it matters.

### 3. Video download via the bridge
- `mcp/youtube-dl.mjs`: find yt-dlp (`OPENOUTLIER_YTDLP`, PATH, `/opt/homebrew/bin`). Run it with an argument array (no shell), with the id checked against `^[A-Za-z0-9_-]{11}$`:
  `-f "bv*[ext=mp4]+ba[ext=m4a]/bv*+ba/b" --merge-output-format mp4 --write-thumbnail --convert-thumbnails jpg --write-info-json --no-playlist -o <stats-named file>`.
- Save to `~/Downloads/OpenOutlier/yt_<name>/`, using the existing `M.fileBaseName` naming. Read the info JSON back into the library.
- Bridge: `POST /youtube/download` (same Host/Origin checks as the other routes) → panel and overlay buttons. When the bridge is not running, the button says so and links to the setup steps.
- MCP: `download_reel` gets a YouTube branch that calls the same module.
- If YouTube blocks formats: a clear error naming the fix (`brew upgrade yt-dlp`, optional `bgutil-ytdlp-pot-provider`). Off by default: `--cookies-from-browser` (it triggers a Keychain prompt).

### 4. Library, MCP and docs
- `mcp/library.mjs`: `isYouTubeId`, `platformOf`, `labelOf`, and parsing of `youtube.com/@name`, `/channel/UC…`, `/watch?v=`, `/shorts/` and `youtu.be/` input. `platform: 'video'` now covers IG + TikTok + YouTube.
- `collect_profile yt/name`: `src/agent-bridge.js` opens `/@name/videos` (then `/shorts`) in a background tab and auto-scrolls.
- `refresh_reel`, `get_reel` (with chapters, heatmap and caption info), `top_reels`, `search_reels`, `account_summary`: YouTube-aware.
- Dashboard and popup: YT badge, platform filter, `@name (YouTube)` labels.
- README: install, use, features, the yt-dlp requirement, and the view-count changes (Mar 2025 Shorts, Aug 2026 all formats).

### 5. Later (not in v1)
- Optional Data API key in settings: exact views, likes, comments and dates for 50 videos per quota unit, without opening pages.
- `get_transcript` MCP tool, from the page's caption tracks, for hook analysis.
- Compare Shorts ↔ Reels / TikTok (extend `src/compare.js`).
- Own channel via the YouTube Analytics API (retention, thumbnail CTR, engaged views) next to My account.

## Risks
- YouTube changes its page JSON often → parser built on fallbacks, fixture tests, and a "no videos found" warning in the panel instead of silent zeros.
- Rounded views on channel tabs → fine for × median (errors under ~10%); exact values come from phase 2 or yt-dlp.
- yt-dlp breaks when YouTube changes SABR/PO tokens → clear error plus an update hint; covers keep working regardless.
- Opening many watch pages could look like bot traffic → throttle, cap N, and only on request.
- View-count method changes (2025, 2026) inflate newer videos → note in the README; the era-adjusted best-time logic already handles drift.

## Settled defaults (were open questions)
1. v1 keeps rounded views + approximate dates from channel tabs; exact values come from watch pages (phase 2) and yt-dlp (phase 3). The Data API key is phase 5.
2. Shorts and long-form are one Library account with two medians.
3. The panel collects the tab that is open; `collect_profile yt/name` collects Videos, then Shorts.

### Biggest surprises
1. **In-app navigation to a video no longer calls `/player` + `/next`.** Clicking a video in the SPA makes one `POST /youtubei/v1/get_watch`, whose body is a JSON **array**: `[{playerResponse}, {watchNextResponse}]` (each part also has `responseType`, `subStreamResponseCompleted`). The inner objects have exactly the `/player` and `/next` shapes. `/player` and `/next` still exist and were captured too (same shapes).
2. **Shorts:** opening a Short in the SPA calls `/youtubei/v1/player` (per Short, also for prefetching the next one), `/youtubei/v1/reel/reel_item_watch` and `/youtubei/v1/reel/reel_watch_sequence`. Channel pages also fire several `/player` calls on load (inline previews).
3. **Shorts `videoDetails` has no `viewCount`** (HTML and `/player`). Use `microformat.playerMicroformatRenderer.viewCount`, which every player response had.
4. **The old renderers are gone everywhere:** no `videoRenderer`, `gridVideoRenderer` or `reelItemRenderer` in any capture. Grids are `richItemRenderer.content.lockupViewModel` (videos/live) and `richItemRenderer.content.shortsLockupViewModel` (Shorts).
5. **Labels are localized, and "B" means different things:** en `63K` / `63 thousand views` / `1mo ago`; tr `63 B` / `63 bin görüntüleme` / `1 ay önce`, decimal comma (`2,8 B`), dot thousands (`801.352 görüntüleme`). English `B` = billion, Turkish `B` = bin = thousand. The parser needs the page language (`document.documentElement.lang`, or `ytcfg.get('HL')`) and a small per-language table (at least en + tr), or it must read the accessibility label words (`thousand`, `bin`, `million`, `milyon`). Prefer numeric fields (`viewCount`, `likeCount`, `originalViewCount`) wherever they exist.
6. A `document_start` fetch wrapper sees `browse`, `get_watch`, `player`, `reel/*` (all via **fetch**, none via XHR). A wrapper installed after load missed `get_watch`, so the hook must stay at `document_start` in the MAIN world.

## Notes from phase 1

Built (uncommitted, branch `youtube`): `src/youtube.js` (parser), `src/youtube-content.js`, YouTube branches in `src/hook.js`, `src/metrics.js`, `src/panel.js` (+ `.seg` switch in `panel.css`), `src/background.js` (covers), `manifest.json`, `tests/youtube.test.js` (20 tests, fixtures en + tr), `dev/youtube-demo.html` (open `http://localhost:8791/dev/youtube-demo.html`, `?hl=tr` for Turkish; preview config `reelscope-demo`).

**Parser API** (`self.OpenOutlierYouTube` in the page, `require('../src/youtube.js')` in Node):
- `parseText(body, opts)` / `parseJson(json, opts)` route any response by shape: get_watch array, player (`videoDetails`/`microformat`), next (`twoColumnWatchNextResults`), reel item (`overlay.reelPlayerOverlayRenderer`), reel sequence (`entries`), browse (`twoColumnBrowseResultsRenderer` = a tab, `onResponseReceivedActions` = continuation). Returns `{ posts, channel, tab, hasMore, items, kind }`. `parsePage(htmlOrScripts, opts)` does the inline `ytInitialData` + `ytInitialPlayerResponse` of a first load (via `extractVar`, a string-aware brace scanner).
- `opts`: `lang` (`'en'`, `'tr'`; anything else = "unknown": rounded labels and relative dates return null, exact numbers still parse; omitted = en), `channel` (continuations never name their channel, so the content script passes the open channel page's facts), `tab`, `now`, `videoId`.
- Grid lockups that carry their own channel avatar link (home/search feeds) are skipped unless it is the same channel.
- `merge(prev, next)`: exact beats rounded for views and comments; a rounded count *above* a stored exact one wins (YouTube rounds down, so the video grew) and is flagged `viewsApprox`; an exact date (`dateApprox: false`) is never replaced by a relative one; `short`/`live` types are never downgraded to `video`; hashtags are unioned.
- Fragments: `/next` records have no `type`; reel-item records carry only likes, comments and the owner. The content script never *starts* a record from a fragment (no `type`): a fragment for a video it doesn't have yet waits in a small buffer (60 ids) and is merged when that video's record arrives (on a Short, `reel_item_watch` can come before `/player`).
- Records: the post shape from the plan, plus `liveNow`, `membersOnly`, `commentsApprox`, `autoCaptions`, `unlisted` when known. Not yet parsed (phase 2): `chapters`, `heatmap`, subscriber count from the watch page, exact date text.

**Language:** the content script uses `<html lang>` (YouTube sets it from its own language setting), but Turkish label words found in the data (`Y.detectLang`) override it, since "B" is the dangerous one. Unsupported languages get a panel notice asking to switch YouTube to English; exact values from watch pages still work there. Turkish "Streamed" label and Turkish members/live badges were not in the fixtures (patterns are guesses: `yayın`, `üye`, `canlı`).

**Content script:** reads the inline data once at startup (never `window.ytInitialData`-style data after SPA navigation), then only hooked responses. `yt-navigate-finish` + a 700 ms URL check handle navigation. Accounts are `rs:p:yt/<handle>`; `profile` holds the channel facts (subscribers, videos, UC id, avatar, verified). A `yt/UC…` account is moved under `yt/<handle>` as soon as the handle is seen. Auto-scroll runs on Videos/Shorts/Live tabs and stops when a browse response has no continuation item (`more[account|tab] === false`), after 10 stale ticks, or on navigation. A grid that had items but parsed to zero posts shows a "YouTube may have changed its page format" notice. No overlay on YouTube yet and no agent commands (the bridge only messages tabs it opened).

**Metrics/panel:** `M.enrich` scores YouTube posts against the median of their (owner, Shorts vs long-form) group; live streams count as long-form; Instagram/TikTok keep one median per list.
